03 / Client project

Email automationn8n · Microsoft Graph, Outlook and OneDrive · GPT-5-class models · Public write-up on GitHub

Multi-Inbox Email Automation for a Document-Services Company

A production system that handles the full first-response lifecycle for a company receiving a high volume of client document requests: it classifies inbound email and web-form enquiries, files attachments, updates a live CRM ledger, and writes ready-to-send replies for human review. Built as two coordinated workflows, a 224-node email pipeline and a 38-node web-intake pipeline, sharing one CRM, one document store and one set of business-rule documents.

How it is built

  • Eight separate reasoning paths, each with its own tightly scoped model call, instead of one large catch-all prompt.
  • Business rules live in an editable reference document the AI layers read at runtime, so staff can change behaviour without a deployment.
  • Thread-aware state matching across mailbox and CRM, so a reply three weeks later still lands on the right record.

Production engineering

  • Root-caused and fixed an infinite-retry loop, a JSON injection bug from unescaped input, and a lifecycle gap that could have billed a client twice.
  • Direct API-level integration work to guarantee correct message threading in cases the standard connector could not handle.

Result

Live in production on a real client inbox, with a phased rollout planned across the company's remaining mailboxes.

08 / Client project

Data pipelinen8n · Structured-data APIs · Provider waterfall · Agentic crawling · AI fallback · Outbound sequencer

Four-Tier Lead Enrichment Cascade

A production enrichment pipeline processing tens of thousands of leads per campaign for a nonprofit client. Two fields are known at intake, a name and a website, and 29 have to be resolved. No single vendor covers that schema, so the pipeline cascades through four sources, each one firing only when the cheaper source ahead of it failed.

Engineering highlights

  • Four source tiers, each firing only for the fields the cheaper tier before it could not resolve.
  • A weighted merge into 29 structured fields per lead.
  • A null-safe AI fallback: a blank field is preferred to an invented one.
  • A closed loop: the sequencer’s reply and bounce events feed auto-suppression back into the CRM sheet.

Result

A live, cost-optimised pipeline resolving 29 structured fields per lead at roughly 96% field-level accuracy, feeding directly into automated outbound sequencing with a closed engagement loop.

04 / Selected work

Monitoringn8n · Postgres · Headless-browser verification · Public write-up on GitHub

Change-Detection and Risk-Intelligence Platform

A monitoring platform for a company whose whole business depends on spotting a specific status change across a very large set of public listings, confirming it against independent sources, and turning confirmed events into qualified sales leads. The hard part is not detection. It is keeping false positives away from people.

Design decisions

  • Append-only event history, so every state change stays auditable instead of being overwritten by the next sweep.
  • Atomic multi-table intake writes, so a half-created record is impossible by construction.
  • A dedicated failure-alerting workflow, added after a silent outage showed that a pipeline without alerting is a pipeline you cannot trust.

Production engineering

  • Diagnosed and fixed real incidents under load, including a database constraint failure, a query timeout that dropped whole batches, and a scoring bug that mis-tiered several hundred records.
  • Built a family of data products on top of the raw detection stream: risk scores, stability indices, geographic rollups and change-event tracking.

Result

A live production system on a fixed weekly cadence, delivered under a milestone contract with the latest milestone signed off and paid.
